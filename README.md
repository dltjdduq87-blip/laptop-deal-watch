# 개인 노트북 다중 쇼핑몰 감시

기존 저장소, 5분 간격 예약 요청, 텔레그램 수신자와 체크포인트를 유지합니다.
**13곳 등록은 13곳 수집 성공을 의미하지 않습니다.** `watch-state/report.json`의 `coverage`가 실행별 실측 상태입니다.

## 대상 및 기준
네이버쇼핑, 쿠팡, 11번가, G마켓, 옥션, SSG, 롯데하이마트, 삼성, LG, ASUS, HP, 다나와, 에누리의 설정된 공개 URL을 점검합니다. 무한한 전체 상품/전체 페이지 탐색은 수행하지 않습니다.
RAM 32GB 이상, 1.6kg 이하, 150만~300만원을 유지합니다. 가격대는 150~190 / 190~230 / 230~300만원입니다. 국내 AS·판매자·재고가 미확인인 가격비교 상품은 검토 후보로 구분합니다. 확정 구매 추천으로 승격하지 않습니다.
일반/최하위 쇼핑몰 회원등급 기준, SKT T멤버십 VIP, 기존 신용/체크/간편결제 수단은 `buyer_profile`에 기록합니다. 개인 적용·중복·배송비 검증 전 확정 실구매가를 만들지 않습니다.

## 수집
- 기존 LG 목록/정확한 모델 수집을 유지합니다.
- 삼성 `ProductGroup.hasVariant` 및 SKU를 읽어 모델별 가격과 RAM을 분리합니다. 다른 모델의 32GB를 선택 모델의 RAM으로 대입하지 않습니다. 누락된 무게는 미확인입니다.
- 다나와의 공개 상품 카드에서 사양과 SSD 옵션별 URL·가격을 각각 읽습니다. 이는 판매처 직접 관측이 아닌 가격비교 사이트 공개 관측입니다. 재고·판매자·국내 AS·배송비는 별도 검증 전입니다.
- G마켓·옥션은 공개 검색 페이지의 상품별 표시 판매가를 읽습니다. 광고 쿠폰가를 결제액으로 대입하지 않습니다. HP는 노트북 카테고리의 상품 카드와 SKU별 표시가, 에누리는 집계 최저가를 구분해 읽습니다.
- 다른 사이트는 명시적인 Product/Offer 구조화 데이터에 한해 파싱합니다. 비어 있거나 구조가 지원되지 않으면 `no_parseable_products`, 접근이 막히면 `blocked`로 기록합니다. 홈페이지 접속만으로 성공 처리하지 않습니다.
- robots 불허, 로그인/접근제한, CAPTCHA를 우회하지 않습니다. API 또는 상품 피드 접근이 필요한 곳은 자동으로 해결됐다고 표시하지 않습니다.
- `market_products`는 광범위 가격 관측, `review_candidates`는 가격·RAM·무게 조건을 충족한 미검증 후보입니다. `products`는 기존 정확한 모델 관측입니다. `coverage_complete`는 모든 설정 사이트에서 실제 상품 수집이 성공한 경우에만 true입니다. true여도 전체 시장/쿠폰/개인 결제창 검증 완료를 의미하지 않습니다.
- 전달된 쿠팡 링크의 상품번호 8837247802 / 옵션 24983983526은 검색 결과 수납함으로 확인되어 `ignored_links`에 사유·근거와 함께 제외했습니다.

## 알림
기존 후보 가격하락·재입고, 공개 쿠폰 문구 변경·삭제, 오류 및 일일 현황을 기록합니다. 쿠폰 문구의 첫 관측은 기준선입니다. 쿠폰 실발급·선착순 잔량·개인 적용·정확한 사전알림 시각은 자동 검증하지 않습니다.
다중 쇼핑몰 검토 후보는 가격순 최대 3건을 실행당 통지하며, 동일 후보/가격은 체크포인트로 중복을 방지합니다. 판매자·AS 미확인을 메시지에 명시합니다.
채널별 전송 완료/대기는 `deliveries`, 이번 실행의 Telegram API 수락은 `delivery_receipts`에 기록합니다. API 수락은 사용자의 수신·열람 확인과 다릅니다.
수집 가능한 사이트가 일부 있어도 수집 미완료 사이트가 남으면 보고서는 partial입니다. 모든 가격수집 실패 또는 필요한 알림 전송 실패는 종료코드 1입니다.

## 실행 및 검증
```
python3 -m pip install -r requirements.txt
python3 -m unittest discover -v
python3 watch.py --dry-run
```
회귀 테스트 34개: 삼성 SKU 그룹, RAM/SSD/VRAM 혼동 방지, 옵션별 가격, 잘못 전달된 비노트북 제외, 접근차단/파싱실패 상태, 기존 알림 재시도/중복방지 등을 확인합니다.

## 운영 및 한계
예약은 `.github/workflows/watch.yml`의 기존 cron을 유지합니다. GitHub Actions의 실행 지연·누락 가능성이 있어 정확한 5분 주기를 보장하지 않습니다. `watch-state` 브랜치에 보고서와 중복방지 상태를 저장합니다. 전송 직후 프로세스 중단이나 저장 실패 시 중복 가능성은 남습니다.
텔레그램: 기존 `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`를 사용하며 수신자 검증을 유지합니다. 이메일은 SMTP 인증정보가 있을 때만 동작합니다. 토큰·채팅 ID·회원 로그인 상태는 저장소에 기록하지 않습니다.
구매 완료 후 감시 중지는 사용자 확인 후 수행하며 범용 수집 코드와 설정 형식은 보존합니다.
