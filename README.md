# 개인 노트북 다중 쇼핑몰 감시

기존 저장소, 5분 간격 예약 요청, 텔레그램 수신자와 체크포인트를 유지합니다.
**13곳 등록은 13곳 수집 성공을 의미하지 않습니다.** `watch-state/report.json`의 `coverage`가 실행별 실측 상태입니다.

## 대상 및 기준
네이버쇼핑, 쿠팡, 11번가, G마켓, 옥션, SSG, 롯데하이마트, 삼성, LG, ASUS, HP, 다나와, 에누리의 설정된 공개 URL을 점검합니다. 무한한 전체 상품/전체 페이지 탐색은 수행하지 않습니다.
RAM 32GB 이상, 1.6kg 이하, 150만~300만원을 유지합니다. 가격대는 150~190 / 190~230 / 230~300만원입니다. 국내 AS·판매자·재고가 미확인인 가격비교 상품은 검토 후보로 구분합니다. 확정 구매 추천으로 승격하지 않습니다.
일반/최하위 쇼핑몰 회원등급 기준, SKT T멤버십 VIP, 기존 신용/체크/간편결제 수단은 `buyer_profile`에 기록합니다. 개인 적용·중복·배송비 검증 전 확정 실구매가를 만들지 않습니다.

## 수집
- 기존 LG 목록/정확한 모델 수집을 유지합니다.
- 삼성 `ProductGroup.hasVariant` 및 SKU를 읽어 모델별 가격과 RAM을 분리합니다. 다른 모델의 32GB를 선택 모델의 RAM으로 대입하지 않습니다. 누락된 무게는 미확인입니다.
- 다나와의 공개 상품 카드에서 사양과 SSD 옵션별 URL·가격을 각각 읽습니다. 이는 판매처 직접 관측이 아닌 가격비교 사이트 공개 관측입니다. 재고·판매자·국내 AS·배송비는 별도 검증 전입니다.
- G마켓·옥션은 공개 검색 페이지의 상품별 표시 판매가를 읽습니다. 광고 쿠폰가를 결제액으로 대입하지 않습니다. HP는 노트북 카테고리의 상품 카드와 SKU별 표시가, 에누리는 집계 최저가를 구분해 읽습니다.
- 다른 사이트는 명시적인 Product/Offer 구조화 데이터에 한해 파싱합니다. 비어 있거나 구조가 지원되지 않으면 `no_parseable_products`, 접근이 막히면 `blocked`로 기록합니다. 홈페이지 접속만으로 성공 처리하지 않습니다.
- robots 불허, 로그인/접근제한, CAPTCHA를 우회하지 않습니다. API 또는 상품 피드 접근이 필요한 곳은 자동으로 해결됐다고 표시하지 않습니다.
- `market_products`는 광범위 가격 관측, `review_candidates`는 가격·RAM·무게 조건을 충족한 미검증 후보입니다. `products`는 기존 정확한 모델 관측입니다. `coverage_complete`는 모든 설정 사이트에서 실제 상품 수집이 성공한 경우에만 true입니다. true여도 전체 시장/쿠폰/개인 결제창 검증 완료를 의미하지 않습니다.
- 전달된 쿠팡 링크의 상품번호 8837247802 / 옵션 24983983526은 검색 결과 수납함으로 확인되어 `ignored_links`에 사유·근거와 함께 제외했습니다.

## 알림
기존 후보 가격하락·재입고, 공개 쿠폰 문구 변경·삭제, 오류 및 일일 현황을 기록합니다. 쿠폰 문구의 첫 관측은 기준선입니다. 쿠폰 실발급·선착순 잔량·개인 적용·정확한 사전알림 시각은 자동 검증하지 않습니다.
다중 쇼핑몰 검토 후보는 가격순 최대 3건을 실행당 통지하며, 동일 후보/가격은 체크포인트로 중복을 방지합니다. 판매자·AS 미확인을 메시지에 명시합니다.
채널별 전송 완료/대기는 `deliveries`, 이번 실행의 Telegram API 수락은 `delivery_receipts`에 기록합니다. API 수락은 사용자의 수신·열람 확인과 다릅니다.
수집 가능한 사이트가 일부 있어도 수집 미완료 사이트가 남으면 보고서는 partial입니다. 모든 가격수집 실패 또는 필요한 알림 전송 실패는 종료코드 1입니다.

## 실행 및 검증
```
python3 -m pip install -r requirements.txt
python3 -m unittest discover -v
python3 watch.py --dry-run
```
회귀 테스트 66개: 삼성 SKU 그룹, RAM/SSD/VRAM 혼동 방지, 옵션별 가격, 잘못 전달된 비노트북 제외, 접근차단/파싱실패 상태, 기존 알림 재시도/중복방지, 판매처별 간접 가격(현금가·카드가·광고·해외 구분), 로컬 혜택 기록의 개인정보 줄 제외 등을 확인합니다.

## 운영 및 한계
예약은 `.github/workflows/watch.yml`의 기존 cron을 유지합니다. GitHub Actions의 실행 지연·누락 가능성이 있어 정확한 5분 주기를 보장하지 않습니다. `watch-state` 브랜치에 보고서와 중복방지 상태를 저장합니다. 전송 직후 프로세스 중단이나 저장 실패 시 중복 가능성은 남습니다.
텔레그램: 기존 `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`를 사용하며 수신자 검증을 유지합니다. 이메일은 SMTP 인증정보가 있을 때만 동작합니다. 토큰·채팅 ID·회원 로그인 상태는 저장소에 기록하지 않습니다.
구매 완료 후 감시 중지는 사용자 확인 후 수행하며 범용 수집 코드와 설정 형식은 보존합니다.

## 11번가 공식 API 연결 준비
상품검색 API 수집기를 구현했습니다. `ELEVENST_API_KEY`가 없으면 네트워크 호출 없이 인증키 필요 상태로 기록합니다. 11번가 API 관리에서 발급받은 키를 GitHub Actions Secret `ELEVENST_API_KEY`에 저장해야 실제 API 검증을 진행할 수 있습니다. 현재 인증키 발급/실 API 호출 검증은 미완료입니다. 응답의 할인모음가는 개인 실결제가로 취급하지 않으며 인증키를 포함할 수 있는 요청 에코는 보고서에 기록하지 않습니다.

## 상태 알림 수정
11번가 API 경로가 지정되면 같은 사이트의 기존 HTML 경로를 중복 요청하지 않습니다. 해당 설정은 삭제하지 않고 `superseded_sources`에 대체 사실을 기록합니다.
텔레그램에는 쇼핑몰별 미완료 사유를 한국어로 표시하며 내부 오류 코드는 보고서에 보존합니다. 가격 관측은 개별 모델/목록을 구분하고 검토 후보 수는 동일 모델의 옵션이 포함될 수 있음을 명시합니다.
상태가 바뀔 때 알리고, 오전 10시 이후 첫 실행의 일일 현황과 겹치면 하나로 합칩니다. 같은 상태를 매번 오류 알림으로 재전송하지 않습니다. 상태 알림 전송 실패는 동일 이벤트로 재시도합니다.

## 노트북용 로그인 준비 · 1단계
Windows에서 `start_windows.bat`을 실행합니다. 사용법과 검증 한계는 [LOCAL_START_KO.md](LOCAL_START_KO.md)를 확인하세요. 전용 브라우저에서 직접 로그인하며 로그인 상태는 PC에만 저장합니다. 이 단계에는 회원 가격·쿠폰 자동 감시 연동을 포함하지 않습니다. 기존 GitHub Actions 감시 설정은 유지합니다.

## 판매처별 간접 가격 (다나와·에누리 상세) · 2026-10-25 추가
- `offers.py`: 목록에서 예산(150~300만원) 안이고 RAM·무게가 조건 밖으로 확인되지 않은 모델의 **상세페이지**를 비교사이트별 실행당 최대 8곳(`offer_detail_limit`) 방문합니다. 에누리는 robots의 Crawl-delay에 맞춰 1초 간격입니다.
- robots 허용 경로만 사용: 다나와 `/info/`(불허 `/info/ajax/`·`/bridge/`는 사용 안 함), 에누리 `/catalog/`(불허 `/api/` 사용 안 함). 그래서 초기 HTML에 표시된 판매처(다나와 약 8곳, 에누리 약 20곳)만 읽으며 전체 판매처 수(`site_offer_count`)와 함께 기록합니다.
- 판매처명은 정확한 이름만 13개 대상에 연결합니다(`SSG.COM`→SSG 등). 네이버페이 아이콘이 있어도 네이버쇼핑으로 분류하지 않습니다.
- 현금가·카드할인가는 기본 판매가가 아닌 조건부 가격으로 따로 둡니다. 카드가는 보유 수단과 대조해 표시만 합니다(하나는 체크카드만 보유 → 신용카드 행사면 해당 없음). 비교사이트 적립금은 `reward_separate`로 분리합니다. 광고·해외 판매처는 기준가에서 제외합니다.
- 상세페이지에서 읽은 RAM·무게는 목록 관측에 보강하고 `state.json`의 `detail_specs`에 캐시합니다. 다음 실행은 이미 조건 밖으로 확인된 모델을 건너뛰고 새 모델을 방문합니다. (실사이트 3회 시뮬레이션에서 에누리 19개 모델 사양 확보, 32GB·1.6kg 이하 독립 모델 5개가 새로 후보에 포함됨)
- 보고서: `offer_details`, `offer_observations`, `offer_errors`, `shop_summary`(쇼핑몰별 직접 수집 상태 / 간접 가격 건수·일반가 최저 / 회원혜택 검증=항상 false).
- 간접 관측은 해당 쇼핑몰의 직접 수집·로그인·쿠폰·재고·판매자·국내 AS 검증이 아닙니다. `coverage`의 수집 상태도 올리지 않습니다.

## Windows 설치 (스마트 앱 컨트롤)
인터넷에서 받은 `start_windows.bat`은 Windows 스마트 앱 컨트롤이 차단할 수 있습니다. 보안 기능을 끄지 말고 `py -3 setup_windows.py`로 설치하세요. 자세한 내용은 [LOCAL_START_KO.md](LOCAL_START_KO.md).

## 전체 제조사 감시 (에누리 조건 필터 순환 수집) · 2026-10-25 추가
- `sweep.py`: 에누리 노트북 목록(robots 허용 `/list`)에 사이트 자체 필터를 적용합니다: 메모리 32/48/64/128GB, 무게 1.7kg 미만(1kg 미만·1.0~1.4·1.4~1.7), 150만~300만원, 중고/렌탈 제외. 조사 시 9,428개 → 674개 모델(LG·레노버·HP·삼성·ASUS·DELL·MSI·에이서·애플 등).
- 실행당 4페이지(약 160개)씩 순환하고 `state.json`의 `enuri_sweep`에 저장합니다. 약 5회 실행에 1회전. 24시간 다시 보이지 않은 목록은 제외합니다. 실사이트 5회 연속 실행: 실행당 약 100초, 671/674개 수집.
- 목록에서 무게·RAM·CPU·그래픽·화면·OS·카드특가·SSD 옵션을 읽습니다. 최종 조건(1.6kg 이하, RAM 32GB 이상)은 코드에서 다시 거릅니다.
- 알림: 같은 모델의 SSD 옵션은 하나로 묶고, 가격대(150~190/190~230/230~300만원)별 **예상가 TOP 3**에 새로 들어오거나 더 싸진 모델만 실행당 최대 3건 알립니다. 첫 1회전이 끝나기 전에는 후보 알림을 보내지 않습니다. 일일 요약에 가격대별 TOP 3을 표시합니다.
- 예상가는 목록 최저가·판매처 가격·보유 카드(KB국민/우리 신용, 네이버/카카오페이) 조건가 중 최저이며 검증된 결제액이 아닙니다. 성능 점수는 만들지 않으며 사양을 그대로 표시합니다.
